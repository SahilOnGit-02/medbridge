# Demo guide

Use only synthetic records. Prepare accounts and sharing before recording, and keep passwords, tokens, private capture files and credentials off screen. Use the actual configured URL and tested commit; do not imply that a staging demonstration is a clinical deployment.

1. Explain the fragmented-record problem and canonical hospital mapping.
2. Show separate doctor/patient entry and the registration/approval boundary.
3. Doctor: find a patient by name, narrow with DOB, confirm ID, open the focused record and review current information and history. Switch category/timeline layouts.
4. Doctor: use the Medical Reports section, filter a report and download the PDF. Use correctly associated report fixtures; an empty list is appropriate where no report exists.
5. Patient: review/edit profile, navigate history and the dedicated Medical Reports page.
6. Patient: change report sharing while retaining another category. In a fresh doctor request, demonstrate that report access fails while that category remains available. Restore the intended sharing state afterward.
7. Explain limited, audited emergency access. It does not bypass report consent.
8. Show verification/recovery using local capture if provider details remain pending, explicitly labeling it as local capture. Use real email only after staging acceptance.
9. Close with implemented scope, test evidence, workflow limitations and remaining release work.

The script is prepared guidance. No demo video has been recorded by this change. Avoid inventing measured UX or clinical outcomes.
